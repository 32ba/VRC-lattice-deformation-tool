# 2.0の内部構成と互換性

2.0.0-beta.1では、既存の機能と保存データを維持しながら、変形評価、移行、編集操作、Previewの責務を分離した。
この文書は保守に必要な構成と契約を記す。試験の再実行方法は[検証手順](validation.md)を参照する。

## 責務の配置

| 場所 | 責務 |
| --- | --- |
| `Runtime/MeshDeformer/` | 公開コンポーネント、保存フィールド、既存APIの互換入口 |
| `Runtime/Model/` | Group/Layerモデル、データの解決・コピー・互換性判定 |
| `Runtime/Evaluation/` | 通常評価とPreviewで共有する数値計算、Mesh出力、一時bufferの所有 |
| `Runtime/Migration/` | 保存データの事前検査、公開版ごとの移行、失敗時の復元 |
| `Editor/MeshDeformer/Authoring/` | Undo・Prefab記録を伴う編集操作と、複数フレームの編集セッション |
| `Editor/MeshDeformer/` | Inspector、Scene Tool、検証、NDMFとの接続、周辺機能 |
| `Editor/Preview/` | Previewの更新、Meshの借用・所有、終了時の復元と解放 |
| `Editor/Legacy/` | 旧Brushコンポーネントの検出とEditor上での移行 |

`DeformationEvaluator`は検証済み入力からGroup/Layerを合成する。
通常の変形と上流Meshを受け取るPreviewで計算を共有し、入出力や更新通知は各adapterが扱う。
RuntimeからUnityEditor/NDMFへの直接依存は追加しない。

`SerializedDeformerReader`は保存状態を補正せずに読み取る。
`DeformerDataResolver`はEmbeddedの読取りと、所有者ごとに独立したProfile評価コピーを解決する。
これらの同期借用viewを、非同期処理用の不変snapshotとして扱わない。

`DeformerEditService`は構造編集のUndo、Prefab override、失敗時の復元をまとめる。
`DeformerEditSession`はdrag開始時の対象と状態を保持する。
Scene Toolのhandlerは入力と操作の寿命を管理し、数値計算・選択・描画を各専用処理へ委譲する。

## 維持する契約

- 既存の型名、namespace、assembly、公開API、script GUID、保存フィールドとSerializedProperty pathを維持する。
- Group/Layerの順序、有効状態、選択、weight、Mask、制御点、Brush変位、Profile参照、BlendShape設定を保持する。
- 元Meshを書き換えず、頂点以外のMesh channel、既存BlendShapeの全フレームとweightも保持する。
- 旧版の補間・BlendShape出力規則は明示的な互換設定で再現する。内部整理を理由に現行規則へ置き換えない。
- Undo/Redo、複数対象の原子的な編集、Prefab Variantの継承・Apply・Revert、保存再読込みを検証する。
- Profile評価で共有assetを変更しない。保存・Embeddedへのコピーは明示操作とする。
- MeshとNativeArrayは所有者が解放する。Preview終了時は借用Meshを復元し、外部処理が割り当てた別Meshを上書きしない。
- ブラシ、頂点選択、ラティスでは、それぞれのmirror、Mask、比例編集、rest-space変換の既存規則を維持する。

## データ移行

[公開版一覧](2026-09-07-published-releases.json)は移行テストの入力であり、42公開版の順序とtagの由来を固定する。
schemaが同じ版も明示的なno-opとして順番に処理し、各境界の保存記録が成功してから進捗を確定する。
未来のversion、壊れたpayload、source不整合を推測で補正しない。
失敗時はraw保存データとPrefab overrideを復元する。

公開YAMLから正確なリリースを識別できない場合は、識別可能な最古のschemaから処理する。
fixtureに記録したtagの由来を、利用者データの推測に用いない。
0.0.1のWorld-space markerが後の保存で失われたデータは自動判別できないため、バックアップまたは明示判断を必要とする。

`HistoricalReleases`の14版と`LaterReleases`の28版は、各公開版のRuntimeで実保存・評価した独立fixtureである。
候補実装の結果を使って期待値を上書きしない。
固定基準fixtureのcommit値は生成元の由来として保持し、履歴整理後のcommitへ機械的に置換しない。

## 文書の保管方針

ここには構成・互換性・検証手順と、テストが必要とする公開版一覧だけを保存する。
個人名、利用者のプロジェクト名、絶対パス、画面記録、実行ログ、端末情報、作業日誌はコミットしない。
検証結果の原本はリポジトリ外に置き、公開文書には再現に必要な条件と結果の範囲だけを記す。
