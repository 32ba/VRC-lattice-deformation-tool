# 操作検証実装の追加レビュー

2026年9月6日、`codex/interaction-quality` の未コミット変更を再レビューした。
対象の基準は `1.4.6-beta.1`。
今回のレビューでは製品コードとテストコードを変更していない。

## P1：コピー前の元メッシュ変更を検出せず、変形を別の頂点へ適用できる

対象は `MeshDeformerClipboard.CopyLayer` の互換性取得前、および `CopyGroup` の同じ処理。
保存済み変形の元メッシュとの対応を検査せず、コピー時点のメッシュから新しい互換性情報を作っている。

Unityの隔離したPreview Sceneで、3頂点のメッシュのindex 1へZ方向0.25の変位を保存した。
その後、元メッシュのindex 1と2の位置を交換し、triangle indexも交換して見かけの形状を維持した。
元コンポーネントの共通Validatorは `MDV003` を返し、元データの対応が失われていることを検出した。
しかしレイヤーコピーと、変更後メッシュの独立複製への貼り付けは両方成功した。
貼り付け先は診断0件で、元の右側頂点用の変位が上側頂点に適用された。
グループ単位でも同じ成功・診断0件を再現した。

コピー前に、保存済みsource identityとtopologyの一致を確認する必要がある。
コピー後の元メッシュ変更を検査する既存テストでは、この経路を検出できない。
修正時はコピー前の頂点・index順変更をレイヤーとグループの両方で固定し、失敗時に元データと既存クリップボードを保持することも確認する。

## P2：無効コンポーネントへの貼り付けでsource drift検査を省略する

対象は `MeshDeformerClipboard.HasValidTargetStorage` の `target.enabled` 条件。
共通Validator自体も無効コンポーネントを検査対象から外すため、条件を外すだけでは解決しない。

既存Brush変形を持つ貼り付け先を無効にし、頂点数を変えずに元メッシュの頂点・index順を交換した。
その変更後メッシュと互換な正常データをコピーすると、貼り付けが成功して保存データが変更された。
貼り付け先を再び有効にすると `MDV003` が発生する。
無効な処理をPreview/Bakeから外す方針と、そのデータに対する書き込みを許可する検査は分ける必要がある。

無効コンポーネントでも、副作用のないsource identity・topology・保存構造の検査を行ってから書き込むことを推奨する。
修正時は無効状態の拒否とデータ不変を確認し、有効化して既存のエラーを隠したり消したりしないことも検査する。

## 検証範囲

Unity MCPで本体の共通ClipboardとValidatorを呼び、レイヤーコピー、グループコピー、無効な貼り付け先の3条件を再現した。
試験は一時生成メッシュと隔離Preview Sceneだけを使い、確認後に破棄した。
クリップボードのstatic状態は試験前の値に戻した。
最後に `HAOLAN` Sceneがdirtyではなく、元の `inner` が選択され、コンパイル中でないことを確認した。

前回の1,002件成功はそのテスト範囲の結果であり、今回の3条件は含まれていない。
今回は全体テストを再実行せず、差分の読解と上記の追加再現を行った。
直ちに全データが消失する問題やEditorクラッシュは今回の範囲では再現していないが、P1は警告なしの誤適用につながるため公開前の修正を推奨する。
